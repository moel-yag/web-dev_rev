## 3. Diagnostic exercise — start here

Before studying Day 1's material, spend 45–60 minutes on this exercise. It will reveal which skills have returned naturally and which need more work.

Don't look up a complete solution. Use your editor, browser and console, and allow yourself to forget things.

## Mini task tracker

Diagnostic

Suggested time: 45–60 minutes · HTML + CSS + JavaScript

Build a small task tracker that lets a user add tasks, mark them as complete, and delete them.

Requirements

- Create a semantic HTML structure with a heading, form, text input, button and task list.
- Style it with CSS. Use Flexbox or Grid and make it responsive.
- Use JavaScript to add tasks without reloading the page.
- Allow each task to be marked complete and deleted.
- Prevent empty or whitespace-only tasks.
- Display a message when there are no tasks.
- Make the interface usable with a keyboard.

Optional challenge: Save the tasks in `localStorage` so they remain after refreshing the page.

What this tests

- HTML: semantic elements, forms and labels.
- CSS: layout, selectors, spacing and responsive design.
- JavaScript: variables, functions, arrays, objects, DOM manipulation and events.
- Problem-solving: empty states, validation and keeping the interface synchronized with its data.

### How to score yourself

Give yourself 0, 1 or 2 points in each category.

| Category | 0 points | 1 point | 2 points |
| --- | --- | --- | --- |
| HTML | Couldn't structure it | Needed frequent references | Built it independently |
| CSS | Couldn't lay it out | Basic styling only | Styled and adapted it responsively |
| JavaScript logic | Couldn't get it working | Worked with help | Implemented the core behavior independently |
| DOM and events | Didn't know where to start | Got some interactions working | All core interactions work |
| Debugging | Stuck on errors | Fixed some with help | Diagnosed and fixed errors systematically |

Interpret your score out of 10

- 0–3: Spend more time on the fundamentals before building bigger projects.
- 4–6: You remember parts of the material; target your weak areas.
- 7–8: Good foundation. Prioritize JavaScript fluency and integration.
- 9–10: Move faster through the basics and focus on projects and deeper concepts.

This score is only a rough guide. A working result is useful, but being able to explain and modify the code matters just as much.

## 7\. How to know you're ready for the next step

At the end of the month, test yourself against these milestones:

- [ ]I can build a semantic HTML page without looking up every element.
- [ ]I can create a responsive layout with Flexbox and Grid.
- [ ]I can write functions and manipulate arrays and objects comfortably.
- [ ]I can handle DOM events and forms without copying a tutorial.
- [ ]I can fetch data from an API and handle loading and error states.
- [ ]I can debug problems using the browser's developer tools.
- [ ]I can build, explain and deploy at least one complete project.
- [ ]I can use Git for basic version control.

Once these are reasonably comfortable, start learning a frontend framework such as React. You don't have to wait until you know every JavaScript feature, but you should understand functions, arrays, objects, modules, DOM concepts and asynchronous code first.

My biggest recommendation: begin with the diagnostic today. Don't spend the first week planning the perfect learning setup.
